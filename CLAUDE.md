# MVOGMBI_Sync_2026.1

Application Python (3.13) qui récupère les ventes Clover (API REST v3 ou export Excel « Ventes d'articles ») et prépare leur import dans Sage 50 Comptabilité Édition canadienne 2026.2 sous forme de facture de vente au client « Vente hebdomadaire », une ligne par article, cumulée sur un jour, une semaine (lundi → dimanche) ou un mois.

Projet sans aucun lien avec le site conceptinformatique. L'utilisateur, propriétaire du Marché MVOG-MBI Sherbrooke, communique en français : répondre et nommer le code en français.

## Commandes

- `python -m pytest` : tests
- `python -m mvogmbi_sync facture --periode jour|semaine|mois --date AAAA-MM-JJ` : fichier d'import Sage `sortie/factures/Vente_….IMP` + détail Excel
- `python -m mvogmbi_sync importer --periode … --date …` : prépare la facture puis l'importe avec `Sage_SA_import.exe <fichier.IMP> <entreprise.SAI>` (version la plus récente sous C:/Program Files (x86)/Sage 50*) ; refuse si points à vérifier, si la facture existe déjà (`tcustr.sSource` pour le client) ou si le doublon ne peut être vérifié (sauf --forcer) ; vérifie la présence de la facture après import ; journal `donnees/journal_imports.csv`. Fichier cible : config.toml [sage_import] fichier_entreprise (copie d'essai tant que le format n'est pas validé).
- `python -m mvogmbi_sync verifier-comptes [--fichier X.SAI]` : règle du propriétaire 15xx (actif) -> 40xx (produits) / 50xx (CMV) ; rapport `donnees/comptes_a_corriger_<fichier>.xlsx`. Aussi lancé par `correspondance` ; `importer` bloque si un article de la facture n'a pas de compte de produits et avertit pour les incohérences.
- `python -m mvogmbi_sync verifier-sage` : teste la lecture directe de Sage
- `python -m mvogmbi_sync correspondance` : lit les articles directement dans Sage (sinon `donnees/Article.txt`) et crée/met à jour `donnees/correspondance_articles.xlsx` (articles Clover -> numéros Sage)
- `python -m mvogmbi_sync rapport --periode jour|semaine|mois --date AAAA-MM-JJ [--par-jour] [--export fichier.xlsx]`
- `python -m mvogmbi_sync inventaire [--export X.xlsx | --saisir X.xlsx]` : inventaire Clover + Sage en un fichier, ou saisie de l'inventaire compté dans les deux (page 5 « 📦 Inventaire »)
- `python -m mvogmbi_sync encaissements --du AAAA-MM-JJ --au AAAA-MM-JJ [--export X.xlsx]` : dépôts Clover à encaisser sur les factures et leur état dans Sage (page « 7. Encaissements »)

## Points d'attention

- **Articles renommés ou supprimés dans Clover** (2026-10-27 : 39 anciens articles bloquaient 34 factures) : renommer dans Clover recrée souvent l'article sous un autre ID ; les ventes gardent l'ancien ID et l'ancien nom (`client.article` -> 404). Toute ligne vendue non reliée est notée dans `donnees/articles_a_relier.csv` (`correspondance.memoriser_a_relier`, aussi par le traitement de nuit ; clé `nom:<nom>` pour un montant sans article, « Article personnalisé » = C0000550 dans Sage) ; à chaque mise à jour de la correspondance, ces articles absents du catalogue sont ajoutés et `proposer_renommes` leur propose l'article Clover ACTUEL le plus ressemblant (même format) et son n° Sage, « À confirmer », méthode « Supprimé ou renommé dans Clover » ; ces anciens articles ne comptent pas dans « plusieurs formats sur un article Sage » (`rapprocher(..., absents)`) ; page 5 : filtre « Supprimés ou renommés dans Clover ». Message « non-recette » (Clover fige isRevenue dans chaque vente) : règle gardée, non facturé, jamais bloquant ; aucun message si le catalogue le compte aujourd'hui comme recette (`RapportVentes.recettes_actuelles`, article corrigé depuis).
- **Règle du propriétaire : deux formats différents = deux articles différents** (« 1kg » / « 500g », « 6-36 » / « 7-36 »). La correspondance ne PROPOSE jamais deux formats différents ; mais une liaison confirmée par le propriétaire (« Confirmer quand même ? » de la page 5) est valide et appliquée, jamais annulée ni comptée dans « plusieurs formats » (règle du 2026-10-28 : ancien nom mal écrit dans Clover, corrigé ensuite) ; sans article Sage au bon format -> « À créer dans Sage ». Plusieurs formats Clover sur un article Sage sans format -> à séparer.

- Prérequis Sage pour l'import : fiche client « Vente Hebdomadaire », onglet Importer/Exporter, case « Ce client utilise mes n° articles » cochée (`tcustomr.bUseMyItem`) ; chaque article doit avoir un compte de produits. `Sage_SA_import.exe` renvoie 0 même en cas d'échec : seule la présence de la facture dans `tcustr` fait foi.
- **Une facture par jour du lundi au jeudi, une seule du vendredi au dimanche** (« Vente 2026-10-23/25 », datée du dimanche, préparée après le dimanche ; règle du propriétaire du 2026-10-26, pour encaisser d'un coup le dépôt du lundi ; n° de facture Sage limité à 20 caractères). Les anciennes fins de semaine facturées jour par jour restent reconnues (`facture.jours_facture`) ; un bloc d'un seul jour (vendredi et samedi déjà facturés) s'appelle « Vente 2026-10-25 » (« Vente 2026-10-25/25 » des essais reste reconnu) ; à l'encaissement, chaque jour de fin de semaine va sur la facture de Sage qui le couvre (`factures_fin_de_semaine`). Même pour un rattrapage mensuel : `--par-jour` (`periodes.blocs_facturation`) met toutes les factures dans un seul .IMP (un seul OK dans Sage). Les ventes anciennes (> 90 jours) sont lues à partir des paiements (`payments` filtrés par date), puis chaque commande par son ID.
- **Règle de facturation (fixée par le propriétaire)** : montant de ligne = ventes nettes Clover de l'article ; prix unitaire = ventes nettes / quantité nette (4 décimales) ; total facture = ventes nettes Clover. Voir `mvogmbi_sync/facture.py`.
- Facture générée : client « Vente Hebdomadaire », mode « Payer plus tard » (dépôts appliqués ensuite), code de taxe « GQ » (TPS 5 % + TVQ 9,975 %) pour les lignes taxées dans Clover (`lineItems.taxRates`), datée du dernier jour de la période, numéro « Vente 2026-10-23 » / « Vente 2026-10-23/25 » (vendredi-dimanche) / « Vente S43-2026 » / « Vente Octobre 2026 », quantités au millième (Sage accepte 4 décimales).
